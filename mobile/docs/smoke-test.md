# 실기기 스모크 테스트 (출시 전)

출시 전에 **실제 안드로이드 폰**에서 손으로 확인하는 절차다. 2026-11 점검
(`docs/audit-2026-11-16.md`)의 P0–P3 수정을 반영했다.

자동 테스트(vitest 단위 + `tests/e2e/app.e2e.test.ts` 컨트롤러 E2E)가 WebView 쪽 로직을 덮는다.
SMS 발송 결과, 권한, 로그인 화면(GeckoView), 공유창, 시계 같은 **네이티브 흐름은 실기기에서만** 확인된다.

> 폰클 로그인에는 **reCAPTCHA(로봇 아님)** 가 있다. 자동입력은 아이디·비밀번호까지만 채운다.
> 보안문자는 매번 사람이 직접 눌러야 하며, 자동화(adb 입력 등)로 통과시키지 않는다.
> 보안 확인에 실패해 로그인이 거절되면 "폰클 보안 확인(reCAPTCHA)에 실패해…" 안내가 뜬다. 이것은
> 비밀번호 오류가 아니다. 저장된 비밀번호는 지우지 않는다.

## 0. 준비

```bash
cd mobile
npm test                       # 단위 + E2E 전부 통과 확인
npm run build && npx cap sync android
cd android
JAVA_HOME="/c/Program Files/Android/Android Studio/jbr" ./gradlew assembleRelease
# (같은 순서를 한 번에: cd mobile && npm run apk — 1.2.17부터 build + cap sync + assembleRelease)
# 산출물: app/build/outputs/apk/release/app-release.apk  (debuggable 아님 — RELEASING.md 참고)

adb devices                    # 기기가 목록에 떠야 함 (USB 디버깅 ON)
adb install -r app/build/outputs/apk/release/app-release.apk   # 기존 데이터 유지하며 갱신

# 로그 관찰(별도 터미널) — 크래시 확인용. 릴리스 빌드는 고객 번호·문자 본문을 남기지 않아야 한다.
adb logcat -c && adb logcat | grep -iE "poncle|sms|AndroidRuntime|Capacitor"
```

- 테스트 문자는 **본인 번호**로만 보낸다. 설정 > 문자 발송 테스트에 내 번호를 저장해 두면 홈의
  '＋ 테스트 대상 추가'도 그 번호를 쓴다(고정 번호 없음).
- 폰클은 실제 계정을 쓰되, 실제 고객 발송·복원은 백업을 먼저 받아 둔 상태에서만 한다.

## 1. 배포 빌드 (P0)

1. `adb shell dumpsys package com.poncleexpiry.app | grep -i flags` → `DEBUGGABLE`이 **없어야** 한다.
2. `adb shell run-as com.poncleexpiry.app ls` → "not debuggable"로 거부되어야 한다.
3. 문자 1건 발송 중 logcat에 `phone`/`text` 값, `due_cache` 내용이 **찍히지 않아야** 한다.

## 2. 발송 무결성 (P0)

1. 실제 발송 ON → 본인 번호 대상 `알림 보내기` → 확인창 `보내기`.
   - "문자 보내는 중…" → "문자를 보냈습니다". 이력에 남고 홈 카드는 `✓ 발송됨`.
2. **비행기 모드 / 유심 없음**: 발송 시도 → 즉시 실패 토스트, 이력에 기록 없음, 카드는 미발송 그대로.
3. **듀얼심 '항상 묻기'**: SIM 선택창을 취소 → 발송완료로 남지 않아야 한다(실패로 표시되거나 기록 없음).
4. **늦게 오는 실패**: 신호가 약한 곳에서 보내고 앱을 열어 둔 채 기다리기 → 몇 초~수 분 안에
   "문자 발송 실패가 확인되었습니다" 토스트와 카드의 `✕ 발송 실패`. 앱을 껐다 켜도 같은 결과.
5. **재발송**: 이미 보낸 고객의 `재발송` → 확인창에 "이미 YYYY-MM-DD 발송됨", 버튼 `재발송`.
   보내면 이력은 한 건으로 갱신되고 이력 카드에 '최초 발송 YYYY-MM-DD · N회'가 보인다.
6. 발송 직후 앱 강제 종료 → 재실행. 실제로 나간 문자는 이력에 있고, 안 나간 문자는 '발송됨'이 아니어야 한다.

- **이력 내구성 (L43, 1.2.17)**: v1.2.16에서 업데이트한 휴대폰에서 기존 발송 이력이 **그대로** 보여야 한다
  (Preferences → `poncle_durable_kv` 1회 이전). 실제 발송 직후 토스트가 뜨자마자 앱을 강제 종료 → 다시 실행 →
  방금 보낸 고객이 이력에 남아 있고 다시 발송 대상에 뜨지 않아야 한다.
- **긴 문자 일부 실패 (L26)**: 여러 부분으로 나뉜 긴 문자 중 일부만 실패하면 실패 사유가
  "일부만 전송되었을 수 있습니다 (긴 문자 N개 중 M개 전송됨…)"로 표시된다(재현이 어려우면 생략).
- **대량 발송 제한 (I2, 30분 30건 — 긴 문자는 분할된 건수로 셈)**: 안드로이드는 긴 문자를 나눠 보낸 **조각마다**
  1건으로 센다(기본 템플릿 한 통 ≈ 4~5건). 본인 번호를 테스트 대상으로 두고 홈에서 **기본(긴) 템플릿**으로 30분 안에 연속 발송한다
  (확인 시트의 '분할 N건' 표시로 한 통의 조각 수를 확인).
  1. 조각 합계가 25건 전후일 때(5조각 템플릿이면 5통째) "최근 30분 동안 문자를 N건(긴 문자 분할 포함) 보냈습니다 …
     창이 뜨면 '허용'을 눌러 주세요" 안내가 **한 번** 뜬다 — 시스템 창보다 **먼저** 떠야 한다.
  2. 조각 합계가 30건을 넘는 발송(5조각이면 7통째 전후)에 안드로이드 시스템 창 "많은 양의 SMS를 보내고 있습니다"가 뜬다.
     '허용' → 그 문자가 정상 발송되고 이력은 `✓ 발송됨`.
  3. 다시 한도에 걸리게 한 뒤 '거부'(또는 창 닫기) → 이력·카드가 `✕ 발송 실패`, 사유가
     "안드로이드 문자 발송 제한(30분에 30건 초과)에 걸려 전송되지 않았습니다 … '허용'을 눌러 주세요"로 표시된다
     ('잠시 후 다시 시도하세요'만 나오면 실패). 휴대폰 제조사·통신사에 따라 한도가 다르면 건수만 기록한다.

## 3. 연습 모드(기록만) (P0)

1. 실제 발송 OFF로 `기록` → 카드 배지 `기록만 됨(미발송)`.
2. 실제 발송 ON으로 바꾸면 같은 고객에 `실제 발송` 버튼 → 보내면 `✓ 발송됨`.
3. 실제로 보낸 고객에게 연습 모드에서 다시 `기록`을 눌러도 실제 발송 기록이 덮이지 않는다.

## 4. 오래된 목록 / 세션 (P0)

1. 어제 이전에 스캔한 상태로 앱을 연다 → D-day는 오늘 기준으로 다시 계산되고,
   "○월 ○일 스캔 결과" 배너가 뜬다. 보내기 전에 스캔일을 밝히는 확인창이 뜬다.
2. 폰클 세션이 서버에서 만료된 상태로 앱을 연다 → 확인 후 '폰클 로그인이 필요합니다' 배너.
   설정의 세션 표시는 '세션 만료'.
3. 세션 만료 상태로 스캔 → '마지막 스캔' 시각이 **바뀌지 않는다**.
4. 로그인 화면이 폰클 메인으로 바로 열려 자동 감지가 안 되면 '로그인 완료' 버튼으로 마친다.
   앱이 실제 세션을 확인한 뒤에만 '로그인됨'이 된다.

## 5. 중복 발송 방지 (P1)

1. 조회 탭이나 미방문 탭에서 보낸 고객 → 홈으로 돌아오면 `✓ 발송됨`(목록 아래로 내려감).
2. 스캔이 도는 중에 다른 고객에게 발송 → 스캔이 끝나도 그 고객은 발송됨으로 남는다.
3. 설정 > 약정 기간에서 약정 개월을 바꾸면 안내 문구가 뜨고, 이미 보낸 고객은 계속 '발송됨'.
4. 홈 목록 순서: 미발송이 위, 그 안에서 만료가 급한(지난 D+N, 오늘) 고객이 맨 위.

## 6. 백업 / 복원 / 내보내기 (P1–P3)

1. **백업 내보내기** → 공유창에서 저장. 대시보드의 백업 알림이 사라진다.
2. 공유창을 **취소** → 두 번째 공유창이 뜨지 않고, 클립보드에 아무것도 복사되지 않으며, 백업 알림은 남는다.
3. **이력 CSV** → .csv 파일로 공유되고 Excel에서 한글·열(만료일·요금제·담당)이 바로 보인다.
4. 내보낸 파일은 앱 캐시에만 잠깐 남는다: 취소하면 바로 지워지고, 공유한 파일은 다음 앱 실행 때 지워진다.
5. **복원**: 다른 고객이 섞인 백업 → "이 기기의 발송 이력 중 N명의 기록이 백업 파일에 없습니다"
   확인창. `합쳐서 복원` → 이 폰의 기록이 그대로 남고 백업의 기록이 더해진다.
6. 복원 후 바로 홈 → 백업에서 보낸 고객이 `✓ 발송됨`. 설정 화면을 나가도 복원한 설정이 유지된다.
7. 미방문 탭에서 '제외'한 고객과 대시보드의 재방문 전환율이 백업/복원 뒤에도 유지된다
   (복원 메시지에 '미방문 제외 N명 추가').
8. 옛 백업(v1 템플릿 포함)을 복원해도 은퇴한 기본 템플릿이 되살아나지 않는다.

## 7. 시점 누락 방지 (P1)

1. 주말·휴무일에 앱을 열지 않은 뒤 스캔 → 그 사이 지난 1단계/유지일이 `D+N 지남`으로 다시 뜬다(최대 14일).
2. 폰클 요금제유지 미결 조회가 실패하면 "폰클 요금제유지 미결을 불러오지 못했습니다" 배너가 뜨고
   해당(요금제 유지) 고객 발송이 막힌다. 다시 스캔하면 풀린다.

## 8. 화면 / 조작 (P2)

1. **하드웨어 뒤로가기**: 확인창 → 닫힘, 설정 하위 화면 → 상위로, 템플릿 편집 중 → "저장하지 않은
   변경 내용" 확인. 홈에서만 앱이 백그라운드로 간다.
2. 키보드가 올라와도 발송 확인창의 `보내기`/`취소`가 가려지지 않는다.
3. 업데이트 확인: 오프라인에서 수동 확인 → "업데이트 확인 실패"(최신 버전이라고 하지 않음).
4. 고객 조회에서 결과가 많으면 "검색 결과가 많습니다 — 더 구체적으로 검색하세요".
5. 시스템 확인창(웹 주소가 제목인 기본 대화상자)이 어디에서도 뜨지 않는다.

## 9. P3 기능

1. **첫 실행 온보딩**: 문자 권한 → 폰클 로그인(✓) → `시작하기` → 홈에서 **자동으로 첫 스캔**이 돈다.
   로그인하지 않고 끝내면 스캔 없이 로그인 배너만 뜬다.
2. **템플릿 삭제**: 템플릿 편집 > 이 템플릿 삭제 → 확인창 → 삭제 후 토스트의 `실행취소` → 원래 자리로 돌아온다.
3. **발송 확인창 글자수**: 문구 아래 "N자 · B/90바이트 · 단문(SMS)" 또는 "장문(LMS)/분할 N건".
   기본 문구로 실제 수신해 보고 장문으로 한 통에 오는지(통신사에 따라 여러 통) 확인한다.
4. **기본 문구**: 새로 설치하면 약정 만료 문구가 "○년 전 휴대폰 개통…"과 "📅 약정 만료: D-n (날짜)"로
   나오고 "홍길동 고객님"처럼 띄어 쓴다. 기존 설치에서 기본 문구를 **고친 적이 없다면** 업데이트 후 새
   문구로 바뀌고, 고친 문구는 그대로다.
5. **휴대폰 날짜 오류**: 설정 > 날짜/시간 자동 설정을 끄고 날짜를 하루 이상 바꾼 뒤 앱으로 돌아와
   스캔(또는 잠시 뒤 포그라운드 복귀) → 홈에 "휴대폰 날짜가 실제와 다릅니다 — 날짜/시간 자동 설정을
   켜 주세요" 배너, 알림 보내기를 누르면 막힌다. 자동 설정을 다시 켜고 스캔하면 배너가 사라진다.
   날짜가 맞는 폰을 하루 넘게 백그라운드에 두었다가 비행기 모드로 복귀해도 배너가 뜨지 않아야 한다
   (판정은 폰클 응답 시점에 잰 시차 기준).
6. **이력 화면**: 건수가 많으면 "총 N건 중 200건 표시"와 `더 보기`. 1000건에서 조용히 끊기지 않는다.
   아래에 '이 폰에만 보관' 안내가 보인다.
7. **접근성**: TalkBack을 켜고 상단 뒤로 버튼("뒤로"), 하단 탭 이름, 실제 발송 스위치("켜짐/꺼짐"),
   토스트 문구가 읽히는지 확인한다.
8. **번호 오류 문구**: 유선번호 고객에게 보내면 "휴대폰 번호 형식이 올바르지 않습니다 (010으로 시작하는 10~11자리)".
9. **요금제명**: 홈/조회 카드의 요금제명이 잘려 보이는지 기록한다(폰클 `listOpen` 응답이 자른 것으로 추정,
   `docs/keepdate-scan-design.md` 참고). `{요금제}`가 들어간 문구는 확인창에서 직접 확인하고 보낸다.
10. **목록 잘림 안내**: 평소 스캔에서는 "일부만 불러왔습니다" 토스트가 **나오지 않아야** 한다
    (폰클 페이지 안전 한도에 걸렸을 때만 표시, 콘솔에 `[poncle] … safety cap` 경고).

## 10. 로그인 (네이티브, GeckoView)

v1.2.17부터 폰클 로그인과 조회는 앱에 내장된 **GeckoView(Firefox 엔진)** 로 한다. 안드로이드
기본 WebView는 폰클 reCAPTCHA v3에서 거절된다(procLogin result 8). 이전 버전에서 업데이트하면
WebView 시절 저장 세션은 쓸 수 없어 **한 번 다시 로그인**해야 한다(저장된 아이디·비밀번호는 유지).

1. **첫 로그인**: 설정 > 폰클 로그인 → 로그인 화면이 뜨고 아이디·비밀번호가 자동입력된다
   (보안문자는 직접). 로그인 → 화면이 저절로 닫히고 '로그인됨' + 스캔이 된다.
   reCAPTCHA 거절 안내가 **뜨지 않아야** 한다(뜨면 GeckoView 전환이 효과가 없는 것 — 보고).
2. **세션 유지**: 로그인 후 최근 앱에서 앱을 밀어 완전히 종료(또는 설정 > 앱 > 강제 종료) →
   다시 실행 → 재로그인 없이 스캔/조회가 된다(저장된 쿠키가 Gecko로 복원됨).
   - **헤드리스 워커** (출시 전 필수): 로그인된 상태에서 앱 강제 종료 → 다시 실행 → **로그인 화면을
     한 번도 열지 않고** 바로 스캔/조회. 수 초 안에 목록이 떠야 한다. 약 20초 뒤 네트워크 오류로
     끝나면 화면 없는 Gecko 세션이 동작하지 않는 것이다 — 결과를 RELEASING.md "Headless worker"에
     기록하고 1x1 GeckoView 대안을 적용한다. 앱을 몇 분 켜 둔 뒤 다시 스캔해도 '세션 만료'가 뜨지
     않아야 한다(워커 페이지가 스스로 로그아웃하지 않음).
3. **로그아웃**: 설정에서 로그아웃 → 스캔 시 '폰클 로그인이 필요합니다' → 앱 강제 종료 후 다시
   실행해도 로그인 상태로 돌아오지 **않아야** 한다.
   - 로그아웃 실패(쿠키 삭제를 확인하지 못함)면 '로그아웃됨' 대신 "로그아웃하지 못했습니다. 다시 시도해
     주세요."가 떠야 한다. 앱을 켜자마자(수 초 안에) 로그아웃해도 '로그아웃됨'이면 실제로 스캔이
     '폰클 로그인이 필요합니다'로 끝나야 한다(B13).
4. **이미 로그인된 상태로 로그인 화면 열기**: 폰클 메인이 잠깐 보였다가 저절로 닫히며 '로그인됨'.
   서버 세션이 만료됐으면 로그인 폼이 저절로 열린다. 둘 다 안 되면 '로그인 완료' 버튼으로 마친다
   (실제 세션을 확인한 뒤에만 '로그인됨').
5. 저장된 비밀번호가 틀리면 1회 실패 후 다음 로그인 화면에서 비밀번호가 자동입력되지 않고 안내가 1회 뜬다.
   reCAPTCHA 거절(result 8)은 이 안내를 띄우지 않고 "폰클 보안 확인(reCAPTCHA)에 실패해…" 대화상자만 뜬다.
   로그인 실패 뒤 비밀번호 칸만 비워지고 아무 안내도 없다면(결과 감지 실패) 약 10초 뒤
   "로그인 확인 필요" 대화상자가 떠야 한다. 이 대화상자가 비밀번호 오류·reCAPTCHA 안내와 **함께** 뜨면 보고한다.
6. '비밀번호 찾기' 등 다른 링크를 눌러도 로그인 성공으로 처리되거나 비밀번호가 저장되지 않는다.
   폰클 밖 주소(외부 링크)로는 화면이 넘어가지 않는다.
7. 직접 입력한 새 아이디·비밀번호로 로그인 성공 → "로그인 정보를 저장했습니다" 토스트 → 다음 로그인 때 자동입력.
   - 자동입력이 되기 전에(느린 망에서 페이지가 다 뜨기 전) 직접 입력하기 시작해도 입력한 값이
     저장된 값으로 **덮이지 않아야** 한다. 저장된 값은 빈 칸에만 채워진다(B12).
8. 로그인 중 화면 회전/다크모드 전환 → 입력과 진행이 유지된다.
9. 폰클이 alert/confirm으로 알리는 오류(비밀번호 오류 등)가 앱 스타일 대화상자(확인/취소)로 보이고,
   누른 뒤 페이지가 멈추지 않는다.
10. 뒤로가기 → 로그인 취소(앱으로 복귀, '로그인됨'으로 바뀌지 않음).
11. **오프라인**: 비행기 모드에서 스캔 → '세션 만료'가 아니라 네트워크 오류로 표시된다.
12. logcat에 쿠키·아이디·비밀번호·응답 본문이 **찍히지 않아야** 한다
    (`adb logcat | grep -iE "MXSID|SCALE|userpw|listOpen"` 결과 없음).
13. (참고) 앱 첫 실행 직후 첫 스캔은 Gecko 엔진 기동으로 몇 초 더 걸릴 수 있다.
14. **빈 화면에 갇히지 않음 (L12)**: 비행기 모드로 로그인 화면을 연다 → "네트워크 문제로 로그인 상태를
    확인하지 못해 로그인 화면을 엽니다…" 토스트와 함께 로그인 폼(또는 Gecko 오류 페이지)이 열린다.
    세션이 만료된 상태에서 폰클 빈 화면이 보일 때 '로그인 완료'를 누르면 안내 토스트와 함께 로그인 폼이 열린다.
15. **select 선택 (L40)**: 로그인 화면(또는 '비밀번호 찾기' 등)의 드롭다운을 누르면 앱 스타일 목록이 뜨고,
    고른 값이 페이지에 반영된다. 목록 밖을 누르거나 뒤로가기로 닫아도 페이지가 멈추지 않는다.
16. **http 차단 (L36)**: 로그인 화면은 항상 `https://m.poncle.co.kr`만 연다(설정의 폰클 주소와 무관).
17. **늦은 세션 복원 (L37)**: 앱 첫 설치 직후처럼 Gecko 기동이 느릴 때 로그인 화면이 먼저 로그인 폼을
    보여도, 저장된 세션 복원이 끝나면 화면이 저절로 닫히며 '로그인됨'이 되어야 한다. 그 사이 새로 로그인했다면
    새 로그인이 유지되어야 한다(스캔이 '세션 만료'로 끝나지 않음).
18. **WebView 시절 쿠키 정리 (L44)**: v1.2.16에서 업데이트 후 첫 실행 → (디버그 빌드에서만 확인 가능)
    `app_webview/Default/Cookies`에 poncle.co.kr 쿠키가 남지 않는다. 앱 UI(설정·이력)는 그대로여야 한다.
19. **응답 없는 워커 (L13)**: 스캔이 연속 두 번 네트워크 오류(각 약 25초)로 끝난 뒤 세 번째 스캔은 워커를
    새로 열어 정상 동작해야 한다(재현이 어려우면 생략, 회귀만 확인).
